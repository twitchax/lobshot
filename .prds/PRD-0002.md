# Summary
The rules engine, headless and deterministic: terrain, shots, wind, turn order, movement, damage
and the event log, with the first mobile (Coilback, carrying Armor's behavior).

# Problem
Everything else (the server, the client's replay and prediction, bots, the lab) runs `sim`. If two
targets disagree on one bit, replays, prediction and golden tests all break, so determinism and
the numbers come first.

# Goals
1. GunBound players' aiming formulas work in lobshot within 0.05 bar.
2. Any recorded log replays to the same state hash on native and wasm32.
3. Coilback can play a full headless game against itself.

# Technical Approach
See `DESIGN.md`, "Fidelity rules" and "Game model". The server owns randomness: wind rerolls,
weather, spawns and starting order arrive as events, so `sim` itself never seeds an RNG for
gameplay. Shots integrate in closed form at fixed sub-steps so the server, the client and the lab
step identically.

# Assumptions
- IEEE-754 basic operations are exact on both targets; only transcendental functions need `libm`.

# Constraints
- No Bevy, no I/O, no clocks in `sim`. It must also build for wasm32 (`cargo make clippy-wasm`).

# References to Code
- `crates/sim/`, `assets/mobiles/coilback/rig.ron`, `assets/maps/tidewall/terrain_mask.svg`.

# Non-Goals (MVP)
- Weather (M2), items and other mobiles (M3, M5), networking and rendering (M2).
